## 3. Tooling and Runbook Implementation

### 3.1 Restore Script Safety Invariants (`scripts/db-restore.sh`)
The restore utility enforces 5 layers of defense:
1. **Production Refusal Gate:**
   - Rejects `turff_db`, `turff_prod`, `turff_production`, `postgres`, `template0`, `template1`, and the value of `$POSTGRES_DB`.
   - Rejection is case-insensitive.
2. **Explicit Confirmation Gate:**
   - Refuses execution unless passed `--confirm` or `RESTORE_CONFIRM=true`.
3. **Pre-Restoration TOC Inspection:**
   - Runs `pg_restore -l` on the decrypted file before creating or altering the target database. If the archive is truncated or invalid, the process halts immediately.
4. **Automatic Plaintext Shredding:**
   - A shell trap (`trap cleanup EXIT INT TERM`) guarantees that decrypted `.dump` files in temporary directories are deleted upon success, failure, or SIGTERM/SIGINT.
5. **No `prisma migrate reset`:**
   - Uses `pg_restore --clean --if-exists --no-owner --no-privileges` exclusively.

|---|---|---|
| **Targeting `turff_db`** | `./scripts/db-restore.sh <file> turff_db --confirm` | `[CRITICAL] SAFETY INTERVENTION: Target database 'turff_db' is a forbidden production name. Refusing execution.` (Exit code: 1) |
